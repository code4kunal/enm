STATUS:   CLOSED 2026-08-19, partly by fixing and partly by distinguishing.

          Availability is now answered per site, not per system. Tyre pressure
          and bus washing report `available: false` at a depot that has
          nominated no `chart_key` line, with a reason naming the key that
          would fix it. `GET /reports/control-charts?site=` gives the depot's
          answer; without `site` it stays the catalogue of what the system can
          answer at all.

          Coolant topping was deliberately left available. It is wired to the
          coolant register, so an empty month there is real data — MBMT has
          never recorded a topping — and marking it unavailable would hide a
          fact the depot should see. That is a separate matter, in the notes
          on the coolant register having no work type routed to it.

Root causes differ and all three are data, not code:

* tyrePressure and busWashing read a checklist line nominated with `chart_key`.
  `select count(*) from checklist_items where chart_key is not null` returns 0,
  and no line on MBMT's D.I or ten-day sheet records either measurement — see
  findings note in PENDING section 6. No nomination is possible today.
* coolantTopping has no source: MBMT has **zero** coolant entries. No work type
  routes to the coolant register, so the snag import can never create one and
  nobody has typed one by hand.

The app is not miscomputing. It is presenting five of six Annexure-IV charts as
working when only one has ever had data, and a depot reading them cannot tell
an empty month from an unwired feed. `energy` already shows the right pattern.
