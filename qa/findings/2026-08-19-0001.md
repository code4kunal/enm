          Offering a button that cannot work would be the actual bug.

          is what produced the mistake. A screenshot cannot show a conditional,
          so an absent feature and a correctly-hidden one look identical.

          That is the rule working, not failing. It is exactly how a depot user
          would read the screen, and the cost is a finding that turns out to be
          a question. The answer belongs in the test: assert the promise
          *conditioned on what the server says*, which is stronger than either
          asserting the button is there or accepting that it is not.
