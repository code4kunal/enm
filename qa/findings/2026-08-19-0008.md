THE DATA IS SAFE. The register total is right every time; fingerprinting works
and a re-import writes nothing. This is the account of the work, not the work.

But the account is the whole point of the screen. `rows_accepted` counts rows
that passed validation, not rows that reached a register, so it overstates by
exactly the number of duplicates — and it overlaps `rows_unchanged` rather than
partitioning with it. An operator re-running a corrected month, which is the
scenario fingerprinting exists to make safe, is told more was written than was.
The preview has the same problem one step earlier: `new_count` is computed from
a natural key, and a snag row has none, so every row previews as new.

Fix by counting what `_commit_snag` actually did: it already returns
`unchanged`, so `rows_accepted` should be `len(rows) - unchanged - rejected`.
The preview needs the fingerprint check the commit already performs.
